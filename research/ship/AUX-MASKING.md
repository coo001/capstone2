# 보조 모듈러스에서 마스크 곱하기

2026-10-10. 논문 §4.1 끝부분과 §4.4(p.18, p.21–22)의 레벨 절약 기법을 OpenFHE에 구현한 기록이다.

## 문제

Algorithm 1(p.14)을 그대로 따르면 마스크 암호문과 공개 위상 평문을 곱한 뒤 rescale해야 한다.
이 rescale이 Q 레벨 하나를 쓴다. 논문의 최종 구성은 이 레벨을 쓰지 않으며 `h=31`에서 총 6레벨이다.
이전 코드는 7레벨이었다.

## 구현

키 생성 (`EncryptMaskOverQP`):

1. 마스크를 평소처럼 스케일 `Δ`로 인코딩해 정수 계수 `m_i`를 얻는다.
2. `X_i = round(m_i · P / Δ)`를 큰 정수로 계산한다. 이로써 같은 마스크가 스케일 `P`로 인코딩된다.
   상대 오차는 `2^-log2(Δ)` 수준이다. `Δ`는 2의 거듭제곱이어야 하며 아니면 거부한다.
3. 출력 dense 키를 `QP`로 확장하고(OpenFHE `KeySwitchGenInternal`과 같은 방법) `Enc_QP(X)`를 만든다.

평가 (`HalfBootstrap`의 `auxMasking` 경로):

1. 공개 위상 `ω^{±a}`를 스케일 `Δ`로 `q0`에서 인코딩하고 계수를 부호 있게 `QP`의 모든 limb로 옮긴다.
   계수가 `q0/4`보다 크면 정확한 이동이 아니므로 거부한다.
2. `QP`에서 네 마스크와 위상을 곱해 더한다. 결과 스케일은 `PΔ`이다.
3. `KeySwitchDown`(OpenFHE `ApproxModDown`)으로 `P`를 나눈다. 스케일은 `Δ`, 레벨은 0으로 남는다.
4. 이후 블라인드 회전과 product tree는 레벨 0에서 시작한다.

기존 rescale 경로는 `MakeFullBootstrapKey(cc, dense, sparse, useFused, false)`로 유지했다.
기본값은 새 경로다. 선택한 경로의 마스크만 생성해 보관한다.

## 검사 (`ship-aux-masking-checks`)

`N=1024`, `h=8`, depth 9, scale 50비트, 첫 모듈러스 60비트, `HEStd_NotSet`, `log2 P = 240`이다.
원시 기록은 [results/aux-masking-checks.txt](results/aux-masking-checks.txt)에 있다.

| 항목 | 결과 |
| --- | --- |
| 같은 키·입력 4종에서 두 경로 비교 | 새 경로의 출력 limb가 정확히 1개 많다 (5 대 4). 최대 오차 `2.12e-7` 대 `2.99e-7`, 두 경로의 차이 최대 `3.28e-7` |
| 출력 메타데이터 | scale, noise scale degree 1, 출력 키 tag가 같다 |
| 남은 레벨 사용 | 제곱·rescale 오차 `1.76e-7`, 그 결과를 다시 부트스트래핑한 오차 `2.23e-7` |
| `h=8`, depth 6 | 새 경로만 동작한다. 기존 경로는 예산 부족으로 거부된다. 오차 `3.19e-7` |
| `h=31`, depth 7 | 새 경로만 동작하며 **정확히 6레벨**을 쓴다. 오차 `2.47e-7` |

기존 검사 4종(half, full, component, fused rotation)과 벤치마크의 `fused` 모드도 새 기본값에서 통과했다.
표준 OpenFHE 라이브러리 코드는 바꾸지 않았으므로 `ship-baseline-checks`는 다시 실행하지 않았다.
half-bootstrap의 출력은 5 → 6 limbs로 늘었다.

## 비용

같은 파라미터에서는 새 경로가 약간 느리고 크다. product tree가 limb 하나가 더 많은 상태에서 계산되기 때문이다.

| 항목 (`N=1024`, `h=8`, depth 9) | rescale 경로 | 보조 모듈러스 경로 |
| --- | ---: | ---: |
| 같은 프로세스 4회 중앙값 | 233 ms | 265 ms |
| 저장 계수 payload | 256,868,352 bytes (10/9 기록) | 263,159,808 bytes |
| 최대 RSS (독립 프로세스) | 278,790,144 bytes (10/9 기록) | 294,780,928 bytes |

payload와 RSS의 rescale 경로 값은 2026-10-09 측정이며 같은 날 측정한 값이 아니다.
이 기법의 이득은 같은 파라미터에서의 속도가 아니라 **필요한 깊이가 1 줄어 더 작은 모듈러스와 링 차수를 쓸 수 있다는 점**이다.
논문이 `N=2^13`에서 부트스트래핑할 수 있는 근거 중 하나이다.

## 보안과 한계

- 새 마스크는 dense 출력 키 아래 `QP`에서 암호화되며 OpenFHE의 HYBRID 평가키와 같은 모듈러스를 쓴다.
  메시지는 sparse 키의 위치·부호에 의존한다. 이 묶음의 보안 분석은 아직 하지 않았다.
- `ApproxModDown`의 근사 오차는 측정 오차에 포함되어 있으나 별도 상계는 계산하지 않았다.
- 논문은 마스크 곱셈을 column 방식 블라인드 회전과도 결합한다(Algorithm 4). 이 결합은 구현하지 않았다.
- 검사 파라미터는 기능 확인용이며 보안 수준과 성능을 대표하지 않는다.
